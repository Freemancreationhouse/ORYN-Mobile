ORYN Android Direct3.7 — Offline Start + Dynamic Header + Travel Wi-Fi

Behavior
- Every true app cold start opens the local ORYN offline library first.
- Header while offline: ORYN Offline.
- After Direct ESP32 activation: ORYN Direct — ESP32 FluidNC.
- After selecting/discovering a Pi/other ORYN table: header comes from that table.
- Saved ESP32 IP/calibration are retained for quick reconnect, but do not force Direct mode on startup.
- Saved Pi/discovered tables are retained but do not force remote backend reconnect on startup.
- Closing/reopening with Wi-Fi off stays in the local 100-pattern library instead of showing the backend reconnect screen.

Travel / different Wi-Fi
- FluidNC stays STA>AP.
- If its saved router is unavailable, FluidNC AP can return as fallback.
- Scan Wi-Fi -> connect FluidNC -> open Wi-Fi network setup -> enter the new router/hotspot SSID/password -> Save -> reboot ESP32 -> put phone on same Wi-Fi -> Find ESP32 on Home Wi-Fi.
- No reflashing is required to change networks.
- Captive-portal / WPA2-Enterprise networks may not work for ESP32; use a simple 2.4 GHz router or phone hotspot for demos.

Preserved
- Direct3.6 stable-session anti-reload/anti-probe protections.
- Offline 100-pattern library.
- Pattern Designer and Pattern Forge.
- Direct ESP32 motion, Home, Theta-Rho conversion and saved calibration math.
- Pi/remote ORYN behavior once selected.
